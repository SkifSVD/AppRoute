# Безопасность и назначение

## Назначение

AppRoute — инструмент для владельца компьютера: он позволяет выбрать свои приложения и указать,
через какой сетевой интерфейс (Wi-Fi, Ethernet, VPN-туннель) каждое из них ходит в сеть.
Аналог ForceBindIP. Проект открытый (MIT), код доступен для аудита.

AppRoute использует низкоуровневые механизмы Windows — внедрение библиотеки в процесс, перехват
Winsock и разрешения имён, изменение таблицы маршрутов. Те же механизмы встречаются и во
вредоносном ПО. Легальность определяется не механизмами, а поведением, поэтому в AppRoute
заложены границы.

## Границы (заложены в код)

- **Только выбранные программы.** Без драйвера AppRoute действует лишь на процессы, которые
  пользователь сам запустил через AppRoute, и на их прямых потомков. Нет фонового сканирования и
  внедрения в уже работающие чужие процессы. С драйвером (отдельное согласие, см. ниже) правило
  действует на любой запуск программы, которую пользователь сам внёс в список по полному пути, —
  как правило брандмауэра Windows, без внедрения во что-либо.
- **Приложения из пакетов — только штатными средствами.** Правило для приложения из Microsoft Store
  или MSIX хранит его идентификатор и действует только через драйвер. AppRoute не запускает exe
  из `WindowsApps` в обход пакета и не внедряется в пакетные приложения: «Запустить» — это обычная
  активация Windows, как из меню «Пуск». Учитываются только пакеты текущего пользователя.
- **Только свои процессы.** Внедрение выполняется только в процессы текущего пользователя
  (сверяется SID токена). Процессы других пользователей не затрагиваются.
- **Денлист.** AppRoute никогда не внедряется в защитное ПО (антивирусы, EDR) и критичные
  системные процессы, даже если они оказались потомками.
- **Прозрачность.** При запуске AppRoute сообщает, какое приложение и через какой интерфейс
  направляется. Библиотека и журнал имеют понятные имена; скрытность и маскировка не
  применяются.
- **Без скрытой персистентности.** AppRoute не прописывает себя в автозагрузку и не ставит служб
  без явного действия пользователя. Служба «AppRoute» (менеджер маршрутов, работающий постоянно)
  ставится только кнопкой в окне после окна согласия и запроса UAC, видна в «Службах» под своим
  именем и с описанием и удаляется там же, где ставилась (или `approute-routes uninstall-service`).
  Служба управляет маршрутами и (с драйвером) фильтрами WFP: не отслеживает запуск программ и ни
  во что не внедряется.
- **Драйвер approute-wfp — только с отдельного согласия и с минимальной поверхностью.**
  - Ставится только вместе со службой, по отдельному флажку в окне согласия (по умолчанию снят) и
    после запроса UAC; виден как служба драйвера «approute-wfp», удаляется вместе со службой.
    Файл — в `%ProgramFiles%\AppRoute`, куда обычные программы писать не могут.
  - Не принимает команд от программ: у него нет ни устройства, доступного из пользовательского
    режима, ни IOCTL. Какие программы и куда, ему сообщают только фильтры и контекст провайдера
    WFP, а управлять ими может лишь администратор (служба AppRoute) через службу фильтрации Windows.
  - Только меняет локальный адрес соединений и привязок программ с правилом на адрес интерфейса
    правила; loopback, link-local и multicast не трогает. Содержимое трафика не видит.
  - Фильтры действуют только на процессы пользователя, давшего согласие (`ALE_USER_ID`), и
    существуют, пока работает служба: сессия WFP динамическая, при остановке службы (или её сбое)
    Windows сама удаляет все фильтры. Без работающего драйвера фильтры не ставятся.
  - Выпуск — только с подписью Microsoft (attestation signing). Тестовая подпись нужна лишь для
    разработки и проверки в виртуальной машине; AppRoute не включает тестовый режим Windows и не
    обходит проверку подписи драйверов.
- **Служба не расширяет права других программ.** Её файлы лежат в `%ProgramFiles%\AppRoute`, куда
  обычные программы писать не могут; из привилегий SYSTEM у неё оставлены только нужные; запускать
  и останавливать её может пользователь, давший согласие, — менять настройки и удалять только
  администраторы. Журнал — в `%ProgramData%\AppRoute`: папка проверяется на владельца, ссылки не
  открываются.
- **Самоограничение прав.** AppRoute не повышает свои права молча. Там, где нужны права
  администратора (изменение маршрутов), об этом сообщается, а согласие запрашивается явно.
- **Обратимость.** Изменения маршрутов и фильтры WFP снимаются при остановке менеджера или
  службы. Без службы они не переживают перезагрузку; служба после перезагрузки применяет их снова.
- **Помощник внедрения не расширяет права.** `approute-inject32/64.exe` нужен только для
  процессов другой разрядности. Сам процессы он не открывает: работает лишь с описателем,
  который ему передал (унаследовал) вызывающий процесс AppRoute, поэтому не получает прав сверх
  вызывающего. Внедряет только hook-DLL AppRoute из своей папки и соблюдает те же запреты
  (денлист, только процессы текущего пользователя).
- **Приватность.** AppRoute не собирает и не передаёт содержимое трафика или историю запросов.
- **Пароли прокси.** Логин и пароль SOCKS5-прокси хранятся только в диспетчере учётных данных
  Windows текущего пользователя, не в конфиге; не передаются через командную строку и окружение и
  не пишутся в журнал. Используются только для прокси из правил этого пользователя.
  Журнал ведётся только по явному указанию (`--log` / `APPROUTE_LOG`) и хранится локально.

## Допустимое использование

Используйте AppRoute только на системах, которыми владеете или на управление которыми имеете
разрешение. Не используйте его для обхода политик безопасности в чужих сетях, для скрытого
перенаправления чужого трафика или вмешательства в чужие процессы.
